# QA-чеклист Service Checker — KAN-6

**Проект:** [Service Checker](../README.md) — учебная Python CLI-утилита для проверки HTTP и TCP.  
**Задача:** [KAN-6 в Jira](https://voldan65.atlassian.net/browse/KAN-6) (для просмотра может потребоваться доступ).  
**Тип:** план тестирования и форма фиксации результатов, **не отчёт о пройденных тестах**.  
**Проверка исходников:** 09.11.2026. **Выполнение тест-кейсов:** пока не подтверждено.

## Подготовка

1. Установить Python 3.10+.
2. В первом терминале из корня проекта запустить `python demo_app.py`.
3. Во втором терминале выполнять команды из таблицы.
4. Для каждого теста заполнить фактический результат, дату, версию Python и ОС. Ставить PASS только после собственного запуска.

Демо-сервер использует `127.0.0.1:8000`: маршрут `/health` реализован с HTTP 200, `/fail` — с 503, все остальные — с 404. Это свойства **прочитанного кода**, а не журнал фактических запусков. В примерах проверяются только локальные ресурсы.

## Тест-кейсы

| ID | Проверка и шаги | Ожидаемое поведение по коду | Факт / статус |
| --- | --- | --- | --- |
| TC-01 | `python service_check.py http http://127.0.0.1:8000/health` | `OK`, статус 200, код завершения 0 | Не запускалось |
| TC-02 | `python service_check.py http http://127.0.0.1:8000/missing` | `FAIL`, статус 404, код завершения 2 | Не запускалось |
| TC-03 | `python service_check.py http http://127.0.0.1:8000/fail` | `FAIL`, статус 503, код завершения 2 | Не запускалось |
| TC-04 | `python service_check.py http http://127.0.0.1:8000/fail --expected 503` | `OK`, статус 503, код 0, так как 503 явно задан как ожидаемый | Не запускалось |
| TC-05 | `python service_check.py http 127.0.0.1:8000` | Ошибка аргумента: нужен полный URL, код 2 | Не запускалось |
| TC-06 | `python service_check.py tcp 127.0.0.1 8000` при работающем демо | `OK`, соединение установлено, код 0 | Не запускалось |
| TC-07 | `python service_check.py tcp 127.0.0.1 65000`, предварительно убедившись, что порт закрыт | `FAIL`, код 2; конкретный текст системной ошибки зависит от ОС | Не запускалось |
| TC-08 | `python service_check.py --json --log results.jsonl http http://127.0.0.1:8000/health` | Валидный JSON в выводе; строка JSONL с `check`, `ok`, `status`, `elapsed_ms`, `checked_at` | Не запускалось |
| TC-09 | `python service_check.py http http://127.0.0.1:8000/health --expected 999` | Ошибка проверки допустимого HTTP-кода, код 2 | Не запускалось |
| TC-10 | Проверка HTTP 500 | В `demo_app.py` нет маршрута 500. Нужен отдельный контролируемый стенд | Не применяется к текущему демо |
| TC-11 | Проверка таймаута | Нужен отдельный управляемый сервер, который задерживает ответ; текущее демо не гарантирует таймаут | Не применяется к текущему демо |

**Важно:** 503 на маршруте `/fail` — намеренное поведение демо, не найденный дефект. Успех проверки означает совпадение фактического HTTP-кода с параметром `--expected`, а не обязательно работоспособность бизнес-функции.

## Автотесты и запись фактов

Запустить из корня проекта:

```powershell
python -m unittest discover -s tests -v
```

Текущие тесты в `tests/test_service_check.py` покрывают HTTP 200, HTTP 503, доступный TCP-порт и некорректный URL. Это **покрытие исходного кода тестами**, но не подтверждение, что они пройдены в окружении проверяющего.

После запуска записать:

- Дата и время (часовой пояс): **не заполнено**
- ОС / версия Python / версия или commit проекта: **не заполнено**
- Запущенные TC-ID и реальные PASS/FAIL: **не заполнено**
- Команды, реальные коды завершения, обезличенные логи или скриншоты: **не приложены**
- Замечания и повторяемость: **не заполнено**
