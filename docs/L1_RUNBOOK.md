# L1: базовая диагностика инцидента

Это учебный чек-лист для первых шагов при обращении «сервис недоступен».

1. Уточнить **что** не работает, **когда** началось, у скольких пользователей, есть ли ошибка/скриншот.
2. Проверить влияние: один пользователь, сегмент или весь сервис; приоритет определяется по правилам команды.
3. Повторить проблему безопасным способом. Для HTTP — проверить DNS, затем TCP-порт и HTTP-код.
4. На Linux: посмотреть `systemctl status <имя>`, `journalctl -u <имя>`, `ss -lnt`, `df -h`, `free -h`.
5. Зафиксировать в тикете ожидаемый и фактический результат, время, окружение, выполненные проверки.
6. Если нет прав или проблема не решается на L1, передать L2 вместе с диагностикой.
7. После исправления проверить сервис и подтвердить восстановление с пользователем.

Не выполнять в реальной инфраструктуре перезапуск, изменение прав и удаление файлов без согласования. Не добавлять в тикеты пароли, токены или персональные данные.
